# Contributing to my projects

Thank you for your interest in contributing — I welcome improvements, bug reports, and small focused PRs.

How to contribute

1. Fork the repository and create a feature branch from `main`:
   - `git checkout -b feat/short-description`
2. Keep changes small and focused (one feature / bug per PR).
3. Write clear commit messages and include tests where applicable.
4. Open a Pull Request with a short description, motivation, and testing steps.

Issue reporting

- Use the issue templates (bug report or feature request) when opening new issues. Provide reproduction steps, environment, and sample data if possible.

Code style

- Please follow existing code style. Use `black` for Python formatting and `pre-commit` hooks if present. Run unit tests before opening PRs.

Testing

- Add unit tests for new features or bug fixes and make sure they pass locally.

Review process

- PRs will be reviewed for clarity, tests, and impact. I usually respond faster to small reproducible PRs.

License & Code of Conduct

- By contributing you agree that your contributions will be licensed under the repository's license. If you'd like to collaborate on larger work, open an issue first to discuss scope.
